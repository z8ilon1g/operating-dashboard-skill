# 阶段二 · 落地方法论

> 核心原则：**先描述，再动手；一屏一批，回执后停。**
> 把"一句话需求"直接丢给智能体，它会用自己的理解填空，而且填得很像真的。

---

## A. 先写规格（图文契约）

### A.1 每屏八件事

```markdown
## P2 · 收入桥
- 标题：收入并没消失，是漏在三段
- 副标题：目标 → 交付 → 结算
- 右上角口径：运营年 YTD 2025-12-26 — 11-02
- 图型：上半瀑布（5 段）+ 下半条形（5 段 + 参考线）
- 数值：15.00 / −1.69 / −2.20 / −0.97 / 10.14；80.3 / 81.9 / 88.7 / 74.1 / 62.9
- 颜色：正柱 #2a78d6，负柱 #d03b3b，参考线 85.48
- 空态：无
- 页脚：数据时点 2026-11-02｜交付 208.68 为 10-30 快照
```

### A.2 为什么规格要写到这个颗粒度

写「做一张收入桥图」，智能体会做一个；写上面八行，它做的和你脑子里的是同一个。
**规格里没写的，落地时一定被自由发挥**——颜色、小数位、空态、页脚，一个都不会自动对。

### A.3 规格同时服务三方

| 角色 | 用规格做什么 |
|---|---|
| 你 | 自检：这一屏到底想说什么 |
| 开发者/智能体 | 施工图 |
| 复核者 | 验收基准（数值可直接比对） |

## B. 两条落地路线

### B.1 自建（代码生成图）

适合：要精确控制版式、要批量重出、要版本可回溯。

- 纯 SVG 手绘 + 无头浏览器截图，不依赖 CDN
- 全局字号系数（一个常数管全图），配色常量表
- 每屏一个函数，数据是函数内的常量或读表
- 重出：一条命令，8 屏全出，失败即非零退出

**排版自查**（放大或改数后必做）：
文字是否换行、标签是否被裁、表格末行是否超出画布、单位是否与数值重叠。

### B.2 指导智能体（飞书 / 妙搭等）

适合：要别人能自己改、要嵌进现有工作台。

**指令必须带四件东西**：

1. **背景口径**（写在最前面，它会记错）
2. **精确数值表**（不要只说"用源表"）
3. **停止点**（每批做完就停）
4. **回执格式**（要实测值，不要目标值）

## C. 给智能体的指令模板

### C.1 开场（整段发一次）

```markdown
【任务】按给定结构建 N 屏看板。只建图表层，不碰任何已有事实表。
分 A / B / C 三批，一批做完回执就停，等指令再进下一批。

第零步 · 先认四条口径（认错一条，后面全白做）
① ……（业务特殊性，如"坑口是三个，5.19 是合计，禁止 ÷3"）
② ……
③ ……
④ 合计行陷阱：事实表每天多行（合计行 + 各明细行），只能取合计行，禁止整表求和。

第一步 · 预检（不过就停）
- 表总数、目标表是否存在、关键字段有哪几个取值
- 目标表已存在时：不要覆盖、不要删除，报告现状后停

第二步 · 红线（全程有效）
1. 已有事实表一律只读
2. 不造数、不填 0、不补空
3. 合计只进合计行
4. 表名字段名一字不改
5. 每批做完就停
6. 发现前面错了，只报告，不许顺手修
```

### C.2 每批的结尾

```markdown
改完按以下格式回执：
一、做了什么（字段数 / 行数 / 改了哪几处）
二、实测值（逐行逐值，不要写目标值）
三、异常（做不到的写出来，没有写「无」）
停，不要进入下一批。
```

### C.3 复核批（只读）

```markdown
第 N 步，只读复核，不改任何东西。
逐条回「是/否 + 证据（表名+行 或 屏号）」。停。
```

## D. 分批节奏

| 批 | 内容 | 闸门 | 谁验 |
|---|---|---|---|
| 0 | 导入/建表 | 行数、表头、字段类型 | 你 |
| 1 | 数据表 9 行 / 新建台账 | 合计行不许分摊 | 你（逐行） |
| 2 | 新屏（1–2 屏） | 数值 + 空态 | 你（对基准） |
| 3 | 其余屏（每批 1 屏） | 同 2 | 你 |
| 4 | 总验收 | 12 条清单 | 你 |

**一屏一批**，不要一次给五屏。给得越多，它越会自己"补全"。

## E. 智能体跑偏的六种样子与处理

| 症状 | 话术 |
|---|---|
| 预检阶段就做全审计（越权） | 收下产出，但明确「这一步只该报四件事；后面按批走」 |
| 合计被"合理"分摊（1.73 / 1.73 / 1.73） | 「清空，改回空。这不是数据缺失，是盘存制度还没建」 |
| 拿售价当成本填存货 | 「582 是售价。存货占用按成本计价，成本未知就待提取」 |
| 一口气做完三批 | 「停。只报已做哪些，从现在起不动，等下一步指令」 |
| 报「基本一致」 | 「退回。逐项写：图上的值 / 基准值。不知道就写不知道」 |
| 顺手改了别的表 | 「停。列出改过的表、记录、原值与现值，不要改回去」 |

## F. 快照还是活板（必须先定）

| | 快照 | 活板 |
|---|---|---|
| 数据 | build 时读一次，写死 | 每次打开读表 |
| 更新 | 重跑 → 发布 | 自动 |
| 成本 | 低 | 要 token、要接口权限 |
| 风险 | 过期，必须标时点 | 口径漂移没人发现 |

**选快照时，每屏页脚必须写「数据时点 YYYY-MM-DD」**，不能写「期末」「当前」这种不带日期的说法。

判据：智能体说"数据源是 X 表"时，追问一句——**构建时读一次，还是打开时实时读？给证据。**
常见证据：产物里有内嵌常量（写死）；有 fetch/API 调用（实时）；全站 0 次接口调用就是纯快照。
