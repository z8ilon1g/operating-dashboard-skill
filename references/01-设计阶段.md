# 阶段一 · 设计方法论

> 顺序固定：**原理 → 指标 → 模板 → 表达 → 数据表**。
> 每一小步的产出都能被下一小步直接使用，不能用的产出等于没做。

---

## 1. 搭建原理：先定四件事

### 1.1 时间口径（最先定，最容易错）

| 口径 | 用在哪 | 判据 |
|---|---|---|
| **YTD（年累计）** | 目标完成率、收入桥 | 与「年度计划」同分母 |
| **月度（业务月）** | 月度经营会、异常监控 | 注意业务月可能不是自然月（本案例：26 日–25 日） |
| **时点（期末余额）** | 应收、库存、资金占用 | **不能用流量表相减** |

**必须写下起算日，不是写「YTD」两个字。**

本案例：三份文档都写「YTD 2026-01-01」，但源看板实际按**运营年 2025-12-26** 起算，且日表首条日期就是 12-26。两种算法差 1.6pp（83.84% vs 85.48%），五段的 pp 全部跟着变。

**判据**：把「起算日」写成具体日期，再用三件事交叉验证——① 日表首尾日期 ② 逐日求和是否等于看板累计值 ③ 反证：去掉首年尾部那几天，累计值是否就对不上。

### 1.2 约束在哪

看板的重心跟着**约束**走，不跟着部门走。

先回答：这套系统现在卡在哪一环？
- 产能卡在采矿 → 看板的头两屏是产量与品位
- 卡在销售 → 头两屏是订单与回款
- 卡在外部（价格战/需求不足）→ 看板的头一屏就该是市场，不是内部效率

本案例：约束在采矿（外部锁定型，19 天环保停产），所以 P1 讲吨流、P2 讲收入漏在哪、P5 讲哪根杠杆值钱——三屏都指向"产量与品位"，没有一屏在讲"降本"。

### 1.3 分层

| 层 | 回答 | 典型屏 |
|---|---|---|
| L1 运营 | 发生了什么 | 主链、库房、校准 |
| L2 经营 | 为什么、影响多少 | 收入桥、资金占用、成本与保本 |
| L3 决策 | 怎么办、先动哪个 | 敏感度、约束卡、十问覆盖 |

**层与层不重复。** 如果 L2 的屏在重复 L1 的数，说明 L1 没做完。

### 1.4 一屏一结论

标题写结论，副标题写路径，右上角写口径。

| ❌ | ✅ |
|---|---|
| 收入分析图 | 收入并没消失，是漏在三段 |
| 库存情况 | 库房网络：库存不是一个数，是七个点 |
| 资金占用分析 | 资金占用：3.34 亿压在路上 |

## 2. 指标推导

### 2.1 先画主链

把业务画成一条流，每个转化点问「掉了多少、为什么」：

```
出矿 → 外运 → 交付 → 结算 → 回款
 188.87  202.03  208.68  174.23  8.80亿
        ↑吃库存  ↑在途    ↓未结算  ↓应收
        13.16    6.65    34.45    1.34亿
```

**主链上的每一段掉数，都是一个候选指标。** 不在主链上的指标（比如"部门费用率"）先放后面。

### 2.2 三问筛选

| 问 | 不通过的样子 |
|---|---|
| 可复算？ | 分子分母说不清、窗口说不清 |
| 可干预？ | 知道了也改不动（如全行业价格） |
| 可决策？ | 数变了不会改变任何一个动作 |

三问有一问答不出，这个指标就是装饰。

### 2.3 分母必须各自独立

案例中五段各有各的目标：

| 段 | 目标 | 完成率 |
|---|---:|---:|
| 出矿 | 235.22 万吨 | 80.3% |
| 外运 | **246.75 万吨** | 81.9% |
| 交付 | 235.22 万吨 | 88.7% |
| 结算 | 235.22 万吨 | 74.1% |
| 回款 | **14.00 亿元** | 62.9% |

外运目标 = 销量目标 × 105%（运产比）。**如果拿 235.22 去套外运，会算出 85.9%，把"落后"判成"领先"。**

结论：五段的完成率**不可横向互算**，图上必须写出来。

### 2.4 缺数据

- 源系统有、没接入 → `待提取` + 虚线骨架
- 概念存在、数据没有 → `待提取` + 一行说明（如"缺吨成本，只能给区间"）
- 真的为零 → 填 0，并说明为什么是 0

**永远不要为了图好看而估算。** 估算出来的数会被拿去开会，然后没人记得它是估的。

## 3. 建立模板

### 3.1 一屏一张表

| 原则 | 做法 |
|---|---|
| 一行一个图形元素 | 一根柱、一段、一个节点，各占一行 |
| 图不做二次计算 | 图上要显示的每个数（含占比、差额）都落到单元格 |
| 排序显式 | 有 `顺序` 列，图按它排，不靠数据表默认顺序 |
| 状态显式 | `数据状态`（待提取/部分/已确认）、`可信度`（A/B/C） |

### 3.2 合计行

- 合计**单列一行**（`CK-SUM`），不并入明细
- 明细行的值**留空**，不许按比例倒挤
- 备注写死一句：「禁止分摊到明细」

判据：如果有人能把合计除以 3 填进明细，说明你没写清楚。

### 3.3 公式字段

能算的不手填：`品位差 = 校准品位 − 暂估品位`、`折纯差 = 出矿量 × 10000 × 品位差 ÷ 100`。

但公式依赖的**单位约定要写死**：品位存 23.5 还是 0.235？差 100 倍。写进表头或说明页。

### 3.4 参数页

所有外部假设（价格、成本、资金成本率、年天数、单价）单独一页，标 `来源` 与 `状态（待财务确认）`。
图上引用的每个参数都要能追溯到此页。

## 4. 确认表达

### 4.1 图型选择

见 SKILL.md 表格。补充三条：

1. **桑基表达"流"，不表达"构成"**。用它看损耗，不用它看占比。
2. **瀑布只做"从 A 到 B 差在哪"**，段数控制在 3–5 段。
3. **雷达别超过 3 条序列**，超过就换成表。

### 4.2 颜色

四支封顶：主蓝（有值）/ 橙（补入、校准动作）/ 红（漏出、差额）/ 灰（待提取、结构）。

**不要用紫色**——除非业务语义里有它。案例 P1 的结算是紫色，与其余蓝阶不统一，是历史遗留。

### 4.3 空态

每屏都要设计"数据没来"的样子：

| 元素 | 有数据 | 空态 |
|---|---|---|
| 卡片数值 | 26px 数字 | 「待提取」/「待校准」，13px，深灰（不是浅灰） |
| 图 | 真实形状 | 虚线骨架 |
| KPI | 数值 + 示例标 | 占位文字 + 示例标 |

**空态也必须可读**——它是常态，不是异常。

## 5. 输出一套数据表

### 5.1 交付清单

- 取数表 xlsx（说明 / 参数 / 各屏 / 字典）
- 图稿 PNG（规格基准）
- 逐图说明
- 搭建指令
- 导入版 xlsx

### 5.2 导入版为什么要单独做

工作版 xlsx 每张表上面有一行标题 + 一段说明，**表头在第 3–4 行**。
飞书/多数工具导入时默认"首行即表头"，导进去字段名会变成标题文字，整表作废。

所以另存一版：去掉标题行与说明行、去掉说明页，表头在第一行。
生成方式：读工作版，找到表头行（有统一表头底色的那一行），只复制表头及其后数据。

### 5.3 验收

- [ ] 每张表行数与设计一致，没有多余空行（导入常补到 10 行）
- [ ] 数字列被识别为数字，不是文本
- [ ] 合计行有值、明细行为空
- [ ] 字典页覆盖所有单选值
